# Attendance import

Open **Payroll Items → DTR Plotting** (`/attendance-import`), or use the DTR Plotting button in Employee Logs.

1. Select a branch and create/select a device profile. Each profile has its own employee-ID mappings.
2. Set the desired **Cutoff start date** and **Cutoff end date**, then upload an original XLS/XLSX report or the existing CSV template. Both dates are inclusive. The full source is retained; only the selected cutoff is plotted and can be saved. Use **Apply cutoff** to change the period on a resumed report without re-uploading. The chosen cutoff is remembered per report. Changing it clears selections and review confirmation while retaining time edits. Dates outside the file coverage remain blank. Overnight shifts belong to their attendance date, including a shift on the cutoff end date that ends the next morning.
3. Choose an employee from the export. Match the device employee ID to the correct payroll employee once, then click **Remember mapping**. All pending dates and future uploads from this device use that saved mapping. Different devices keep separate mappings even when employee IDs repeat. Changing a mapping retains unsaved time edits and resets the employee review confirmation. Saved historical entries keep their original employee.
4. Review the full In/Out dates, breaks, attendance type, and default-shift override. A device may label an ordinary night shift as overtime; explicitly correct that classification when appropriate.
5. Missing punches remain blank. Enter a recorded/manual break or explicitly choose no break. A blank day is not automatically an absence.
6. Select dates/intervals in the employee DTR table. Break treatment, attendance type, and shift override are editable on each row. Use **Review** for original punches, full overnight dates, conflict choices, or skipping an interval. Check **I reviewed the employee, punches, break, dates, and classification** below the table, then click **Save reviewed DTR for this employee**. Changes to dates, rules, selections, or employee mapping clear that confirmation. Each interval is saved in its own transaction; errors stay on the affected row and successful intervals cannot be submitted twice.
7. Existing matching regular/rest-day or overtime attendance defaults to **Keep existing**. Select **Replace** only after checking the displayed existing record. If a record changed after preview, refresh and review again.
8. Return to Employee Logs. Imported intervals have an **Imported** source label. Existing entries are labelled **Manual / Legacy** because their historical origin was not recorded.

Uploads and original raw punches are retained privately. Resume recent imports on the import page. Only the uploader can access their batches; branch permissions apply to device selection, mapping, preview, save, and source downloads. A same-day matching log prevents a duplicate on a fresh upload as well as on retry.

## Database setup

Run the additive migration after installing the code:

```sh
php artisan migrate --path=database/migrations/2026_10_27_000002_create_attendance_import_tables.php
php artisan migrate --path=database/migrations/2026_10_27_000003_add_attendance_import_cutoff.php
```

This creates four import/device/mapping tables. The existing payroll tables are not rebuilt. Existing employee details, shifts and manual attendance remain in place. The old direct CSV-save endpoint now requires the reviewed import workflow; the new page accepts the existing CSV columns.

Manual and new imported intervals share `AttendanceLogWriter`. Its existing calculations are retained; Sunday rest-day selection and repeated night-differential saves were corrected during extraction. Payroll already generated for a cutoff is not automatically regenerated by an attendance edit. Review and regenerate the affected payroll using the established workflow.

Overtime with a break must be split into separate intervals using the manual flow; the existing overtime formula does not deduct breaks. Unknown layouts fail with a message rather than guessing column meanings.

## Checks

```sh
php vendor/phpunit/phpunit/phpunit
```

`AttendanceParserTest` covers date headers, both monthly column groups, typed Excel times, overnight rollover and missing punches. `AttendanceImportTest` covers preview isolation, remembered mappings, payroll parity, conflict review, stale previews, retries, missing inputs, overnight dates, authentication, branch isolation, source ownership and repeated night saves. Tests use an in-memory SQLite database.
